# Owlink's text file types: one CFBundleDocumentTypes entry each, with its own
# document icon (Resources/DocIcons/<icon>.icns, made by tools/icon/doc_icons.py).
#
# Ranks: the labelled rows are LSHandlerRank None. They carry the icons and
# never make Owlink the default on their own: Launch Services binds a type
# to the app with the most specific claim before it looks at rank, so an
# exact "public.css" claim even at Alternate beat Safari's and VS Code's on a
# test Mac, and on a clean macOS 26 took md, json, swift, py, sh, csv and
# toml from TextEdit. Once the user picks Owlink for a type (Settings or
# Get Info › Change All), Finder takes the icon from that type's row.
# The "*" row is Alternate and lists exactly what 0.2.x's one Text entry
# listed, so which app opens what without a choice is the same as in 0.2.x
# (checked on a clean macOS 26 and with a VS Code-like app installed).
# Scripts/bundle-app.sh builds Info.plist from this file; DocumentTypes.swift
# (Settings › Default editor for…) has the same list, and a unit test keeps
# the two in step.
#
# label | icon | name | content types (first = the one Settings sets) | imported declaration
# The last column is "-" for a type the system declares, else
# "<conforms to, comma-separated>;<extensions, comma-separated>": declared
# only for types macOS's CoreTypes lacks, with the identifiers Apple's Xcode
# already uses for them, so the declarations agree.
# The "*" row is the catch-all for any other text, with the unlabelled icon.
